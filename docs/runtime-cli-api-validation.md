# Runtime 真实 API 验证 CLI

## 问题与范围

现有 agent_cli.py 直接运行 AgentLoop，不能验证 P5 Runtime 的作用域、取消控制和结果交付。用户需要一个可以自己使用真实 API 测试的入口。

新增根目录 runtime_cli.py，每次启动运行一个独立任务；不提前实现 Harness 或 Session，不改现有多轮 CLI。

## 选择与理由

- 通过既有 ModelConfig.from_env 和 bootstrap 创建组件，复用适配器与工具注册，提供商差异不进入 Runtime。
- 复用 agent_cli.Console 显示既有事件，避免复制显示逻辑或为了单个入口重构旧 CLI。
- 使用 runtime.stream 和 run.events 完整消费事件，显示文本增量、工具状态及唯一 Agent 终态。
- 结束后只打印 RunResult 的类别、原因和安全错误摘要，不输出整个结果或对话历史。
- CLI 创建并拥有模型，等 Runtime 退出作用域后再关闭；模型关闭失败显示单独提示，原本成功的进程改以失败码退出。
- SDK 重试默认 0，便于真实验证时看清一次调用的故障；与旧 CLI 默认 2 不同，可显式调整。

## 取消测试

SIGINT 处理器把 Ctrl+C 转为事件循环中的 runtime.cancel()，使当前事件消费继续直到取消终态与异常传播完成。退出时恢复原信号处理器。

--cancel-after 使用事件循环定时器，在指定秒数后请求相同的取消操作；运行结束时移除定时器。定时可能在 API 启动前生效，此时不应期待已经创建模型流。运行在期限前完成时保留成功结果。

此入口面向主线程中的命令行进程。取消依赖底层模型和工具配合，不强制终止阻塞代码。反复 Ctrl+C 不会绕过 Runtime 的清理等待。

## 使用和观察

运行命令、环境变量、预期结果及退出码见 README 的“Runtime 真实 API 验证 CLI”部分。通过 python runtime_cli.py --help 查看全部参数。

模型名由用户指定；不自动切换提供商。真实模型可能直接回答，因此步数上限测试需要实际观察到工具调用请求，不能仅凭提示词宣称工具边界已被测试。

该入口用于观察真实服务接入和运行控制，不替代离线测试中对调用次数、资源所有权和双重故障的精确断言。

## 验证结果

- python runtime_cli.py --help：成功，显示真实 API、步数与取消选项。
- 新增 tests/test_runtime_cli.py，共 11 项离线测试，覆盖成功、工具往返、步数上限、模型/框架异常、定时取消、模拟 SIGINT、正常结束取消定时器、模型关闭失败、非法参数及缺少密钥。
- python -m unittest discover -s tests -q：全部 169 项通过。
- 测试通过注入假模型隔离网络，未读取或输出真实密钥，未调用真实 API。

本次为 P5 的用户验证入口，不改变 P6/P7 的阶段完成状态。
