# CLI 多轮对话与成功历史交付

## 问题与范围

原 agent_cli.py 每次只接受一个任务，回答后退出，用户无法追问。
本次只接入进程内串行多轮对话，属于 P6 的一个独立小任务；不提前实现 Harness、持久化或多用户服务。

## 为什么这样设计

仅保存最终回答会丢失工具调用、工具结果以及 assistant 消息中的 continuation；
从显示事件重新拼接也无法取得完整 ToolResult。
因此给已有 AgentCompleted 增加 messages 元组，Loop 正常成功时交付完整历史快照，
CLI 直接保存并在下次追加 user 消息。保持事件流作为唯一消费入口，不引入 AgentResult 或共享可变历史。

messages 默认为空元组以兼容旧的事件构造，实际 Loop 成功事件一定携带完整历史。
字段 repr=False 避免普通 repr 展开历史；显式 model_dump 仍包含历史，不应作为默认日志。
模型适配层和工具结果转换无需改动。

## 交互与资源

- 不传 --prompt：持续显示“你> ”，每次回答后等待下一条输入。
- /exit 或 EOF 正常退出；空输入忽略；Ctrl+C 取消并结束会话。
- --prompt 保持单次执行，方便脚本调用。
- 模型、工具执行器和 Loop 在一次 CLI 会话内复用，消息保存在该 run 调用的局部变量中。
- 每次用户输入开启新的 Loop 运行，步骤编号与 max_steps 上限重新计算。
- CLI 在退出时关闭自己创建的模型客户端。

只有成功结束才采用完整历史。模型错误、非成功终态或取消结束会话，并明确提示重新启动。
不自动重试、回滚或续接失败历史，避免遗漏已发生的工具副作用和未完成工具调用。

## 限制

历史仅在当前进程内保留，退出后丢失；没有上下文压缩，长对话可能达到模型上下文上限。
失败时结束整个会话，暂不支持从失败节点恢复或原地新建会话。
此次未调整工具选择提示词、工具路径展示或推理事件；P5/P6 的完整验收仍待后续任务。
