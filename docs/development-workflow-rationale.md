# 开发流程规则调整说明

## 本次任务与路线图的关系

本次小任务只调整 AGENTS.md 中的开发与文档规范。它属于项目基础规范维护，
用于支持 ROADMAP.md 中当前 P3 核心数据结构阶段及后续任务，不代表完成了 P3 的任何功能。
验收标准是三条要求均明确写入规则，且与原有文档分工一致。

## 为什么这样做

- 开始前阅读 ROADMAP.md：先理解当前阶段、依赖与验收目标，避免局部实现偏离项目的学习路线。
- 一次只完成一个小任务：让每次改动都能独立理解、验证和复盘，防止直接推进整个阶段导致范围失控。
  大需求先拆分，本次仅完成其中一个任务，其余留待后续推进。
- 完成后在 docs/ 留下 Markdown 文档：代码和变更清单能够展示做了什么，但通常不能解释为什么。
  记录问题、方案理由与取舍，便于学习 Agent 构建时回看设计过程。

## 取舍与改动范围

将执行规则合并到“修改原则”，将任务说明要求合并到“文档维护”，沿用现有结构。
AGENTS.md 保存持续规则，ROADMAP.md 保存路线和进度，docs/ 保存每次任务的设计理由。
文档长度按任务复杂度控制，不要求为简单改动写冗长报告。

本次只修改 AGENTS.md 并新增本说明，没有修改模型、工具或 Agent 实现。

## 验证与限制

人工核对三条要求均已写入，检查 Markdown 空白与改动范围；本次为文档变更，未运行代码测试。
这些规则约束后续工作流程，实际功能仍须在对应小任务中完成并验证。
