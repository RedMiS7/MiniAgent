# Agent Loop、Runtime 与 Harness 职责调整

## 为什么调整

此前 P4 同时包含循环逻辑和运行管理，P5 只验证复用却未说明 Harness 提供什么能力，容易误导实现边界。
本次只调整路线图的职责与术语，不实现新功能。

## 职责与取舍

Agent Loop 负责模型与工具之间的循环，以及当前任务 Messages 的组装。
Runtime 负责一次 Run 的状态、执行限制、取消与资源生命周期。Loop 需传递异常与响应取消，具体控制策略由 Runtime 管理。
Harness 组合 Model、Tools、Loop 和 Runtime，提供运行入口、工具授权配置及 Events 汇集，支持通过依赖组合复用。
Session 负责跨轮对话状态，在 P6 接入 Harness；P4 的当前任务消息并不等于完整 Session 管理。

将 Runtime 和 Harness 放在 P5，是为了先学会循环，再补齐可复用的运行环境。
这些名称在本项目中用于划分职责，不要求逐一建立类、继承层次或独立框架。
P0 至 P3 的已有方向、单 Agent 范围和最小版在 P5 交付的目标保持不变。

## 验证与限制

核对 P0 至 P7 的顺序、任务与验收标准；确认运行控制位于 P5、Session 位于 P6，保留原有九个完成项。
检查文档格式；本次未修改代码，未运行功能测试。
