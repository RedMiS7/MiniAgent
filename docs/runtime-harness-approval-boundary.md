# Runtime / Harness 第二轮：取消、工具失败与审批边界

## 为什么需要这次收敛

第一轮的“失败即结束”可能混淆工具失败与 Run 失败。当前 ToolExecutor 会将工具错误转成结构化结果，AgentLoop 将结果回传模型；保留这一行为才能让模型根据错误修正后续行动。禁用框架自动重试并不禁止这种正常的工具反馈循环。

本轮同时明确调用方退出、入口复用和人工审批的责任，避免 Runtime 逐渐承接交互策略。

## 选择与取舍

- 运行作用域退出时取消未完成任务并等待清理。显式作用域增加少量调用语法，但避免依赖生成器垃圾回收来终止工具。
- Harness 首版顺序复用，活动 Run 未清理完成前拒绝新 Run。这样先验证独立运行的正确性，不提前承担共享模型和工具的并发契约。
- 首版人工审批由 Harness 接入；Runtime 只负责执行控制与生命周期。具体审批规则、交互方式和拒绝反馈仍在访谈中。
- 模型或执行框架故障结束 Run；工具返回错误仍交回模型。已执行副作用不回滚，框架不自动重试或恢复。
