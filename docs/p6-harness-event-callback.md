# P6 Harness 事件回调汇集

## 问题与范围

已有事件流能表达完整过程，但调用方每次需要自行消费并展示，缺少 Harness 统一的
观察入口。本次只完成事件汇集和运行关联，不实现自动重试、恢复、Session 或事件持久化。

## 方案理由

Harness 增加同步 on_event(run, event)，直接以每次独立创建的 Runtime 对象关联事件。
底层事件类型不变，不恢复 RunEvent，不添加 RunState，也不额外创建公共 Run 包装类型。
需要自己的日志 ID 时，调用方可以在回调中映射所属 Run，不强制所有调用方使用 UUID。

单纯在调用方消费流时转发，会漏掉提前退出后的取消终态。因此 Runtime 增加可选的
单参数事件发布观察回调，Harness 负责绑定所属 Run。Runtime 每次发布过程事件以及
收尾确定的最终事件时通知一次，终态通知前结果已确定、Loop 清理已结束。
保留原有拉取推进模式：回调不会绕开消费背压，也不会在调用方退出后启动新调用。

回调拿到深拷贝，避免只冻结顶层模型而仍可能修改嵌套数据；普通展示异常及回调显式
抛出的 CancelledError 被隔离，不会当作执行失败触发重试。明确 run.cancel() 仍可取消。
不捕获 KeyboardInterrupt/SystemExit 等进程控制信号，不承诺抵抗任意恶意回调。
同步回调应快速返回，不创建事件总线或无限队列；拒绝 async 回调，以避免遗漏 await。

## 改动与验证

修改 Harness/Runtime 的事件发布接点，将 harness_cli 的 Console 展示迁入统一回调，
原事件消费保留以推进运行。修改 README 示例和 P6 进度，不标记完整 P6 已完成。

新增 10 项离线测试覆盖：全量顺序及独立 Run 关联、持续回调故障不重放写入、收尾后
终态可查询、提前退出与无人消费时取消终态、原始模型异常保留、回调 CancelledError
隔离、显式取消、嵌套载荷隔离以及拒绝 async 回调。
运行 .venv/Scripts/python.exe -m unittest discover -s tests -q：全部 216 项离线测试通过。
未调用真实模型或搜索服务。

## 限制

通知不保证外部展示成功，不自动记录或重试丢失通知。调用方仍应完整消费事件；提前
退出作用域才触发取消收尾，单独 break 不等同于退出。仅支持快速同步通知，慢回调仍会
阻塞事件循环。运行关联使用对象身份，若用于持久日志，需要由调用方分配自己的标识。
P6 剩余的复用示例、多适配器验收、重试与恢复仍需后续独立任务。
