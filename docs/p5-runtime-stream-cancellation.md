# P5：流式运行作用域与主动取消

## 要解决的问题

前一小任务只提供 await runtime.run(...)，内部消费全部事件。调用方不能展示实时进度，也没有运行级取消接口。本次补齐流式消费、显式作用域和幂等取消，同时保留已有结果和异常语义。

范围仍限于 P5 Runtime；不实现 Harness、审批、Session 或 CLI 接入，不修改模型适配器及工具实现。

## 使用方式

```python
from miniagent.agent import AgentLoop, AgentRuntime

runtime = AgentRuntime(AgentLoop(model, executor))
async with runtime.stream(messages, options, max_steps=12) as run:
    async for event in run.events():
        show(event)
        # 需要提前停止时 break，然后退出 async with。

result = runtime.result
```

也可继续使用 await runtime.run(messages, options, max_steps=12) 消费完整运行；两个入口共享同一执行路径，同一 Runtime 仍只能启动一次。

- events() 只允许在作用域内消费一次，不支持多个消费者或作用域外续读。
- 退出作用域时，未完成的 Run 被取消并等待清理；已完成 Run 保留原终态。
- 单独 break 不能替代退出作用域：活动工具仍可能继续当前操作，作用域才是可靠收尾边界。
- runtime.cancel() 是同步取消请求，可由同一事件循环中的控制任务调用。它不代表清理完成；等待 run 协程或退出 stream 作用域才能确认收尾。
- 启动前 cancel() 直接将 pending 变为 cancelled，不创建执行任务；之后尝试启动同一实例仍按单次启动规则拒绝。
- 重复 cancel() 不重复向执行任务注入取消；结束后 cancel() 不覆盖结果。
- cancel() 不提供跨线程同步保证。

## 执行与事件设计

Runtime 创建一个自有执行任务，消费者请求下一条事件时才继续推进 Loop。内部仅保留一条待交付事件，用 demand / ready 两个信号协调，不累积事件队列，不提前读取后续模型或工具调用。

这让调用方在模型完成、工具开始前或某个工具完成时退出，能够阻止下一次调用；正在运行的当前工具仍由原 Loop 取消并等待。普通事件沿用现有 LoopEvent 类型，不新增事件包装和底层 run_id。

Runtime 在继续推进 Loop 前、收到事件后检查取消标记，即使模型捕获取消后返回响应，也不会继续启动工具。取消不能回滚已完成的工具副作用。

终态事件在 Loop 收尾后交付，并由最终 RunResult 生成。模型异常时交付一次 AgentFailed，随后继续消费会抛出原始异常；即使调用方在失败事件处 break，作用域退出也会传播执行异常。清理失败不会先向 UI 发出成功事件再改成失败。

消费者离开后，未消费的中间事件可能被取消终态替代；这里是实时事件流，不是可回放的审计日志。状态与结果保存不依赖消费者收到终态事件。

## 取消与资源所有权

取消请求只作用于 Runtime 自有执行任务。Loop 继续负责关闭模型流、取消并等待当前工具任务；Runtime 不关闭借用的模型或执行器。

作用域收尾使用 shield 等待执行任务。调用方在清理期间再次取消，不会把第二次取消传给执行任务；清理结束后仍传播调用方取消。执行任务尚未进入时只设置取消标记，避免任务在启动前就被取消而无法保存终态。

Runtime 已进入终态收尾或关闭 Loop 流时，只记录新取消请求，不打断关闭操作；清理完成后未发布的正常候选结果按取消结束。已经发布的终态不改变。

正常提前退出作用域会完成收尾并返回，结果为 cancelled；在 events() / run() 中观察到主动取消时，会在取消事件后传播 CancelledError。模型与框架异常仍保存失败摘要并传播原始异常。作用域中展示代码自身的异常会触发收尾；清理正常时继续传播该展示异常。

先用单项测试确认缺少 stream 接口，再实现。新增测试随后复现“正常终态收尾中 cancel() 打断清理”，增加关闭阶段保护后通过。

python -m unittest discover -s tests -q：全部 142 项通过，其中 Runtime 共 32 项，本次新增 18 项。覆盖：

- 文本增量在模型完成前交付，普通事件顺序及单一终态。
- 作用域不消费事件就退出、调用边界 break、正常完成事件处 break。
- 启动前取消、模型执行中取消、工具执行中取消和重复取消。

- 第一个工具完成后退出，不回滚该操作，也不执行第二个工具或下一轮模型。
- 未收到终态事件也能查询结果；借用模型不被关闭。

## 取舍与剩余限制

消费驱动会让较慢的显示影响执行推进，这是换取明确调用边界和有限缓冲的取舍。未主动消费时不执行模型调用；没有脱离作用域继续运行的后台任务模式。

任意工具或模型内部需要配合取消及正确实现自己的 finally；不能保证强制终止阻塞代码，也不承诺回滚副作用。Runtime 的关闭阶段保护不替代第三方组件自身的取消安全。

执行故障与清理故障同时发生时仍采用原 Loop / Python 异常链，RunResult 只摘要最终传播出的异常。完整双重故障交付和 P5 整体验收留到下一小任务；本次不勾选 P5 完成。
