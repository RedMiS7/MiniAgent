# P3 复查：按事件流交付结果

日期：2026-09-17。

## 结论与理由

核心类型、校验转换和三类事件定义已有实现；P3 整体仍需补齐组件交接约定与组合验收。本次仅检查并记录，不修改功能代码或路线图勾选状态。

此前进度检查中的“Agent 最终返回结果”不应理解为必须增加 AgentResult 或单独返回 Message。按本轮讨论的事件流方向，模型事件交付回答，AgentCompleted 标志任务成功结束，即可表达 Agent 结果。这样可以复用已有类型，避免重复包装。该方向尚未完整落入项目契约文档和组合测试。

## 完成情况

- 模型消息、请求、响应、工具定义与调用、续接状态，以及工具内容和结果已统一为 Pydantic 类型。
- 严格类型、角色、结束原因、调用 ID 配对、JSON 合法性及结果转消息已有校验与测试。
- AgentEvent、LLMEvent、ToolEvent 已采用固定 type 的判别联合，共 13 种具体事件；事件职责和关联方式已有文档。无需恢复 RunEvent。
- Model 和 ToolExecutor 已有统一接口；整体交接约定部分完成。

## 剩余的两个小任务

1. 固化事件流和组件交接约定。明确最终 ResponseCompleted 与 AgentCompleted 的关系，正常终态后结束流；明确 length/refusal/content_filter 的处理，AgentFailed 与异常传播的关系，以及取消、消费者提前关闭流时的行为。消费者已经关闭流时，不能承诺它必定收到终态事件。消息追加、工具结果回传和 continuation 保留也应统一记录。
2. 补齐组合契约测试。通过假模型、真实 ToolExecutor 和模拟工具完成一次请求、执行、结果回传、最终响应及 Agent 终态的交接，覆盖工具成功和失败回传，断言 ID 与续接状态保持一致。现有 test_simulated_failure_round_trip 是手工构造的字段关联测试，并非完整组件组合验证。
