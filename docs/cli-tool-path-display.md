# CLI 文件工具目标路径展示

## 问题与选择

此前工具状态显示内部 call_id，用户无法知道读取或修改的是哪个文件。
这是展示层问题：Loop 已经转发完整 ResponseCompleted（包含工具调用参数）和以 call_id 关联的 ToolEvent，
无需修改执行循环或往底层事件重复添加路径。未来前端可以按同样的关联方式渲染。

本次属于 P6 的 CLI 展示小任务，仅修改 Console 和使用文档，复用既有交互测试。

## 实现与边界

CLI 收到完整响应时，仅提取 list_files、read_file、write_file、edit_file 的 path，
以 call_id 保存显示标签。工具开始和终态显示工具名、路径、状态及耗时，隐藏 ID。
路径保持模型请求中的工作目录相对路径；它是请求目标，不表示路径已通过权限校验或操作已成功。
解析失败、路径缺失或类型错误时退回工具名，不影响执行器原有的校验和失败结果。
不展示写入内容、替换文本、命令参数或完整 JSON。路径使用 JSON 字符串格式转义换行和控制字符。
标签在模型响应和 Agent 开始时清理，工具终态后移除，防止跨调用误用路径。

例如：
```text
[工具开始] read_file · "README.md"
[工具成功] read_file · "README.md" · 0.002s
```
