# P6 模型有限重试与 CLI 故障演练

## 范围

用户明确本阶段处理模型请求失败与工具错误，程序崩溃恢复留给后续持久化会话。
采用指数退避和随机抖动，并保留能在 CLI 手动配置错误的测试入口。
本次不创建 RunState、不自动重放工具、不添加恢复点，不修改 Loop 或 Runtime。

## 实现与理由

Harness 显式注入 RetryingModel，默认保持不重试；RetryPolicy 指定额外次数和延迟上限。
每个逻辑模型步骤独立计数，适配层已有 LLMError.retryable 决定是否临时故障，不复制
提供商状态码判定。对未向上游交付事件的失败请求进行重试，同一消息及工具结果深拷贝
传入每次尝试。每次先关闭旧流；清理异常直接停止，保留原始异常链。
已携带显式异常原因的错误保守地不重试，避免包装器透传的清理故障被误当作单纯超时。

第 n 次等待均匀分布在 0 至 min(cap, base*2^(n-1))，逐次上限倍增到 cap 后不增长。
使用 asyncio.sleep，可在等待期间取消。已交付任何模型事件均不重试，避免展示混合内容
或重复解释工具增量。保留原模型所有权，Harness 关闭自有原模型而非重复关闭包装器。

create_harness 为其构建的主模型关闭 SDK 重试，不修改原配置。调用方注入模型时需自己
关闭模型内部重试，避免以读取适配器私有字段的方式破坏统一接口。harness_cli 保持 SDK
重试 0，默认启用 Harness 额外两次重试。on_retry 为同步安全诊断回调，输出次数、实际
等待及错误码，不是运行状态或第二套事件历史，不记录完整请求。

## CLI 测试接口

--offline 不读取 API 密钥、不连接模型/MCP，使用本地 echo 和脚本化模型。
--fault-error 指定 timeout/connection/rate_limit/server 等临时错误，或 authentication/
permission/invalid_request 等不可重试错误；--fault-count 和 --fault-step 控制次数与步骤。
--fault-after-partial 在报错前交付模拟文本，用于验证部分输出后禁止重试。
目标步骤通过成功完成的模型响应计数，不通过 HTTP 尝试计数；失败重试仍留在原步骤。

--fault-tool-count 仅在离线模式令 echo 执行前返回结构化失败。离线模型看到失败后发起
具有新 ID 的调用，这是模型决策，不是工具执行器重试；仍受 max_steps 限制。
真实模式可使用模型故障注入，注入的尝试不请求 API，注入结束后调用真实模型。所有
注入默认关闭，测试代码放在 examples，MCP 搜索和工具审批不被更改。

## 验证

新增 22 项测试覆盖退避上限、全抖动取值、次数耗尽、不可重试和未预期异常、部分输出、
失败流清理、取消等待、请求副本与计数重置、模型所有权、SDK 禁重试以及 CLI 注入路径。
OpenAI 和 DeepSeek 使用真实适配器与 SDK、模拟 HTTP 429 验证同请求重试及连接关闭。
CLI 演练验证工具完成后模型重试而工具只执行一次；工具错误回传后新调用和步数限制。
运行 .venv/Scripts/python.exe -m unittest discover -s tests -q：全部 242 项离线测试通过。
CLI --help、工具完成后模型重试和工具失败后继续调用的命令行演练均通过。
未使用真实密钥、未调用真实模型或搜索 API。

## 限制与取舍

本次不处理已交付部分模型输出的恢复，不保证网络超时的远端请求未产生计费。
工具结果不确定时不自动重放，现有工具错误作为信息交回模型；离线注入不模拟已经发生
但未确认的写入。SDK 自带的服务端重试提示未由 Harness 额外实现，本次采用用户指定的
指数退避与全抖动。没有跨进程恢复或持久化。
